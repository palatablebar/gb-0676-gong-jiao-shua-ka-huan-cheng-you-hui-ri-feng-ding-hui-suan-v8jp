# 数据定义

刷卡事件以event_id去重，card保留前导零。route支持1路/01等别名。event_time必须带偏移；业务日为Asia/Shanghai。result仅success可作为行程，失败刷卡隔离。reported为实扣人民币元。票价F1至2026-11-01前为2元，F2为2.50元。

跨线路换乘必须在上一次实际付费行程后60分钟内，恰好60分钟排除。同线路无优惠；零付费行程不能延长换乘锚点。先扣1元换乘优惠，再对卡号业务日施加6元封顶。每条基本票价=实算扣费+换乘优惠+封顶优惠。

业务ID和超大整数按文本保形；Decimal参与数量金额计算，对外序列化为字符串。哨兵集合定义在app/values.py，缺失值不能当零。所有时间带UTC偏移，先转UTC比较，业务日按指定地区划分。区间统一[start,end)。重复业务键保留第一条、完全相同行计重复；值冲突行隔离且保留原值。空文件、全空白、仅表头分开拒绝。

运行清单包括输入sha256、规则版本、参数、生成时刻与耗时。源行编号以CSV解析器的物理结束行号表示，引号内换行不增加记录数。输入超过4MB返回413，非法表头和类型返回422，失效版本复核返回409。

## 银行回执

回执列为`receipt_id,event_id,card,amount,received_at,final`，均按文本保形，`received_at`必须带偏移。`amount`为银行实扣人民币元，`final`表示终结（true/1/是）或部分（false/0/否）。

同一`receipt_id`只采用首次到达取值：完全相同的重试计重复，值冲突的回执隔离且不改写首条。同一行程可有多条部分回执，金额在终结回执到达后累加确认；终结回执之后到达的回执不重复计入，标为终结后回执，需人工裁决。`card`与行程不一致或找不到对应行程的回执进入回执隔离，未裁决前不得封存。

## 回执未齐时的权益口径

裁决采用“确认制”：只有含终结回执的行程参与换乘锚点与日封顶计算，未回执行程不提前占用额度、也不作为换乘锚点。替代方案“应享制”会让未落账行程提前占额，已否决。终结回执到达即按新的已确认集合整体重算，逐程给出补扣、退款或不变。

守恒：基础票价合计=应扣合计+换乘减免合计+封顶减免合计；已到账合计+补扣合计-退款合计=应扣合计；逐程净额=应扣-已确认到账。任一不成立则重算失败，旧版结果保留。回执集合按行程、回执号、金额、到达时刻、终结标记与参数形成摘要，同摘要重算只复用版本，不产生第二笔补扣或退款。回执未对平（有待回执、无主回执、冲突或终结后回执未裁决）时`seal_ready`为false，日结不封存。原始刷卡与每份回执原文按sha256留档，可下载核对。
